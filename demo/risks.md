# 风险与对策

基于 findings.md 对 DeepSeek Harness 插件/市场生态检索结果的提炼：

| # | 风险 | 对策 |
|---|------|------|
| 1 | 第三方插件市场（如 dsh-plugin-hub）来源多元、质量参差，可能混入恶意或低质插件 | 仅从官方「插件中心」或可信渠道安装；安装前查看插件来源、作者与社区评价 |
| 2 | 插件安装即获得较高运行权限，供应链攻击（npm 投毒、仿冒包名如 dshmarket）风险高 | 优先使用带安全审核流程的市场（如 dsh-plugin-market 的 vet 机制）；核对包名与仓库地址，避免拼写仿冒 |
| 3 | npm 分发渠道（@nanmicoder/dsh-plugin-market 等）绕过市场审核，缺乏统一质量与安全把关 | 对 npm 安装来源做哈希/版本校验，审查其依赖树，最小化安装面 |
| 4 | 插件发布审核机制文档（阿里云开发者文档）非官方权威来源，流程可能滞后或不准确 | 以官方文档为准交叉验证；关注插件仓库 issue 与更新频率，及时卸载停更插件 |
| 5 | 插件市场每日更新、数量庞大（10000+），兼容性与 DSH 版本适配风险 | 升级 DSH 前检查已装插件兼容声明；对关键插件做版本锁定并保留回滚方案 |
| 6 | 工具类市场入口插件（如 DSH-Plugins-Marketplace）本身是第三方插件，可能存在「已安装判定」绕过或权限滥用 | 限制市场入口插件的权限；定期审计已安装插件列表，移除冗余入口 |
