# 关键用户旅程（User Flows）

> 文档编号：UX-03 | 隶属：02_UX_DESIGN | 依据：PRD §6 工作流、§7.3/§7.4/§7.5/§7.6、§6.3 异常自愈
> 版本：v1.0 | 日期：2026-11-15 | 角色：UI/UX顾问（t28a-W3-ux）

---

## 1. 阅读说明

- 每条旅程按**步骤化表格**展开：`用户动作 / 界面反馈 / 背后Agent角色`。
- **背后Agent角色**一列只作工程视角注记，用户界面**永不显示**这些角色名（PRD §4.2：用户只面对一个「向导」）。
- ⚠ 标记 = 出错/等待等情绪敏感支路；⏱ = 超过 5 秒进度提示触发点（interaction-spec §5）。

## UF-01 首次启动与两道门选择

**目标**：让零基础用户在 1 分钟内无歧义选定模式并进入对话。
**页面**：P0 启动欢迎 → P1 两道门 → P2 会话工作区（见 sitemap §4）。

| # | 用户动作 | 界面反馈 | 背后Agent角色 |
|---|---------|---------|--------------|
| 1 | 双击打开应用 | P0：向导问候「你好呀，我是你的向导助手」+ 一句「你的内容保存在你自己的电脑上」 | 系统初始化（无Agent） |
| 2 | 点「开始」 | 进入 P1 两道门页，两张卡片并排 | 向导Agent路由加载 |
| 3 | 读卡片 | 左卡大标题「快速做一个能用的」（徽章：快消型）3 条特征；右卡「长期慢慢打磨」（徽章：长期迭代型）3 条特征 | — |
| 4a | 点某张卡的「选这个」 | 卡片高亮，底部确认条：「好的，就按〈卡片名〉来。以后想改也可以。」+「进入对话 →」 | 模式写入项目元数据（埋点#1 项目创建） |
| 4b | （拿不定主意）点「你帮我决定」 | 弹出说明：「听起来你想先试试看？那我建议〈快速做一个能用的〉，做完不合适随时换。」+「就听你的」/「我再想想」 | 向导Agent按意图关键词推断推荐 |
| 5 | 点「进入对话 →」 | 切入 P2，向导打招呼并给出示例想法 | 需求分析师激活 |
| 6 | （支路⚠）事后想换模式 | 设置页（P5）提供切换；界面承诺与 PRD §3.3 一致：快消型完成后可升级长期迭代型 | 工程经理（后台处理转换） |

**设计要点**：两道门不可跳过（PRD §3）；任何选择都有「以后能改」兜底，消除「选错=废掉」恐惧（反馈纪要 A1-02）。

## UF-02 需求对话 → PRD + 原型确认（多轮卡片选择）

**目标**：把一句模糊想法磨成可确认的 PRD + 可交互原型；用户全程不接触术语。
**页面**：P2 会话工作区 + P3 预览。
**背后并行关系**：需求分析师（挖需求）∥ UI/UX顾问（同步出原型），对用户呈现为同一个向导。

| # | 用户动作 | 界面反馈 | 背后Agent角色 |
|---|---------|---------|--------------|
| 1 | 用自己的话说想法（如「给班里做个投票页面」） | 向导复述确认：「好主意！投票页面，明白了」 | 需求分析师；UI/UX顾问并行启动（埋点#2 每轮对话提交） |
| 2 | 进入第一轮追问 | 3–5 个问题以**卡片单选**逐个出现（PRD §7.6 渐进式；每题末附「你帮我决定」） | 需求分析师出题、UI/UX顾问同步记录界面含义 |
| 3 | 点选卡片（或打字补充） | 选中的卡片打勾；向导确认「记下了：〈选项人话〉」再出下一题 | 两角色并行消费同一轮答案 |
| 4 | 重复 2–3 轮 | 问题从「要什么」到「什么算好用」逐步深入；对话轮次与修正次数被记录（埋点#12 满意度推断数据源） | 需求分析师动态调整上限；UI/UX顾问开始产出原型 |
| 5 | （⏱）等待第一版原型 | >5s 出现进度条 + §7.5「等待中」原文 + 阶段小字「正在画页面样子（第 1 步/共 2 步）」 | UI/UX顾问生成单文件HTML原型（§7.2） |
| 6 | 收到原型卡片 | 消息流出现卡片：缩略说明 +「打开原型看看 →」；同时轻提示「已自动备份：画好第一版页面」（快照时机：初版生成，§7.4） | UI/UX顾问交付；视觉模型后台自查截图（§7.2） |
| 7 | 点「打开原型看看 →」 | 切入 P3 预览区，顶部引导「看哪里不顺眼？直接点它试试」 | — |
| 8 | 看预览（满意/不满意） | 不满意 → 走 UF-04 点选纠错循环；满意 → 点「整体都还行，去确认」 | UI/UX顾问接收反馈（埋点#5 原型预览确认） |
| 9 | 确认 PRD + 原型 | P2 出确认卡：「我们把想法写成了〈一份小计划〉和〈页面样子〉，都确认后就开工。」+「确认开工」按钮 | 需求分析师定稿精简PRD；裁判Agent作第一道关（长期型：全量硬约束+软约束；快消型：核心项） |
| 10 | 点「确认开工」 | 「好，开工了！我会在安全环境里做好再给你看。」；快照「确认开工前」（快照时机：用户确认修改前后，§7.4） | 快消型：架构设计师/工程经理隐于后台自动决策（§3.1）；长期型：架构设计师→前台请确认方案（§3.2） |

**异常支路**：裁判Agent退回文档 → 向导说明「我再补充完善一下计划，很快」，不向用户暴露退回细节；快消型退回上限 2 次后提示人工介入（PRD §9.3）。

## UF-03 编码进度等待与异常回滚体验

**目标**：让用户在长时间等待与失败场景中**始终安心**，感知不到源码与报错的存在。
**页面**：P2（进度与消息流）、P4（回滚后的时间轴）。背后机制 = PRD §6.3 异常自愈。

| # | 用户动作 | 界面反馈 | 背后Agent角色 |
|---|---------|---------|--------------|
| 1 | 已确认开工，等待 | 消息流出现进度提示条：<5s 仅「正在做…」；**⏱≥5s** 显示 §7.5「等待中」原文：「我正在帮你生成可运行的版本，这个过程只发生在安全环境里，不会影响你的电脑文件。」 | 全栈开发+测试Agent并行工作；快照管理器已存「开工前」快照 |
| 2 | 继续等待 | ≥40s：进度条下补阶段小字（如「第 3 步：检查质量，快好了」）；≥90s：文案替换为 §7.5「操作超时」原文 +「催我」按钮（埋点#10 关联） | 编程Agent持续执行/自修复 |
| 3 | 点「催我」 | 温柔回应：「收到！我加把劲。」（不展示技术日志） | 调度层提升优先级提示（埋点#10） |
| 4 | （支路⚠）第一次失败 | 用户**无感知**：进度条呼吸继续，后台悄悄重试 | 编程Agent自动修复（第 1/3 次） |
| 5 | （支路⚠）3 次仍失败 → 熔断回滚 | 进度条短暂变暖色但**无红色大弹窗**；随后消息气泡 §7.5「修改失败」原文：「刚才的修改没有成功，我已经帮你回到上一个正常版本，你的内容没有丢失。我们换个思路试试？」+ 按钮「换个思路」/「先看看时间轴」 | 熔断触发→快照管理器回滚到上一健康快照→快消型：编程层换方案重试（§6.3），不倒回需求阶段 |
| 6a | 点「换个思路」 | 进度条重启（回到步骤 1 的等待循环） | 编程Agent采用新技术方案（埋点#10 自修复触发：最终结果=熔断后重试） |
| 6b | 点「先看看时间轴」 | 切到 P4：可见「异常回滚前」自动快照记录，当前版本已指回健康点 | 快照管理器（埋点#6 用户主动撤销的邻近事件流） |
| 7 | （成功）修改完成 | §7.5「修改成功」原文：「改好了，你看看效果？不满意随时告诉我。」+「看看效果 →」跳 P3 | 测试Agent跑全量GWT→裁判Agent判定通过→交付 |
| 8 | 长期迭代型差异 | 涉及设计约束不可实现时：向导出示**变更说明卡**（生活语言）请用户确认后调整方案，不倒回需求阶段（PRD §6.2） | 架构设计师+工程经理前台出具说明 |

**设计要点**：失败对用户永远被翻译成「回到上一个正常版本」，禁止出现「错误/异常/失败代码」字样；全屏永远不出现源码或日志。

## UF-04 预览 → 点选纠错 → 自动刷新循环

**目标**：把「哪里不对劲」变成可执行的修改，用户只需**指一下**（PRD §7.3）。
**页面**：P3 预览区主循环。

| # | 用户动作 | 界面反馈 | 背后Agent角色 |
|---|---------|---------|--------------|
| 1 | 打开预览 | 预览画布呈现原型（模拟数据）；顶部引导「看哪里不顺眼？直接点它试试」；可点元素悬停时显示虚线高亮 | UI/UX顾问提供可交互原型（§7.2） |
| 2 | 点击不满意的元素（如投票按钮） | 元素旁弹出**标注气泡**：「你想把这里改成什么样？」+ 快选（换颜色/改文字/换个位置/说点别的）+ 自由描述框 +「先记下来」/「算了，不改了」 | 交互层捕获点击目标及上下文（§7.3 行为 1–2） |
| 3 | 选择快选或输入一句话（如「更醒目一点」） | 气泡收起；右侧出现清单「想改的地方（1）」：「我点了【投票按钮】，想让它变成：更醒目一点。」可单条「不改了」撤销 | 向导Agent将点击位置+上下文转成修改规约（§7.3 行为 3）——**仅记录未执行**（反馈纪要 A2-02 两段式） |
| 4 | 可继续点其他元素 | 清单累加（想改的地方（2）…）；每条独立可撤销 | 同上 |
| 5 | 点「让向导开始改 →」 | 出现确认前快照提示「已自动备份：修改前」；进度提示条（⏱≥5s 走 §7.5「等待中」） | 快照管理器（快照时机：用户确认修改前，§7.4） |
| 6 | 等待修改 | 进度条呼吸；阶段小字「正在改你点的那 2 处」 | UI/UX顾问规约→编程Agent（前端开发）执行（§7.3 行为 4；埋点#7 点选纠错） |
| 7 | 修改完成 | 预览区**交叉淡入自动刷新**（§7.3 行为 5）；按钮样式已更醒目；消息/浮层显示 §7.5「修改成功」原文；快照提示「已自动备份：把投票按钮改得更醒目」 | 测试Agent回归相关GWT→裁判Agent校验 |
| 8 | 满意 / 再点 | 满意 →「整体都还行，去确认」回 P2；不满意 → 回到步骤 2 循环（次数不限，均被记录，构成认知摩擦数据 §12.6-R3） | 循环 |
| 9 | （支路⚠）这次改失败 | 自动回上一快照，预览恢复；气泡 §7.5「修改失败」原文；清单保留，可换说法再试 | 编程Agent自修复≤3次→熔断回滚（§6.3） |

## UF-05 时间轴一键回滚（线性回滚）

**目标**：让「后悔」零成本且不可怕；用户不理解「分支」也能放心用（PRD §7.4）。
**页面**：P4 时间轴页。

| # | 用户动作 | 界面反馈 | 背后Agent角色 |
|---|---------|---------|--------------|
| 1 | 从侧边或快照提示条点「历史足迹」 | P4：页首说明「像游戏存档一样，我自动帮你备份了每个重要时刻，你不用记着点保存」 | 快照管理器 |
| 2 | 浏览时间轴 | 单条直线时间轴，自上而下：今天 15:24「把投票按钮改得更醒目」〔当前版本〕／15:23「修改前自动备份」／14:02「画好第一版页面」／13:47「确定要做投票页面」／13:45「刚创建项目」 | — |
| 3 | 点某个旧版本的「回到这里」 | 二次确认弹窗：「要回到〈画好第一版页面〉吗？放心，回去了之后，现在这份也会存起来，不会丢。」按钮「对，回到那里」/「再想想」 | 快照管理器预检 |
| 4 | 点「对，回到那里」 | 轻纱过渡 300ms + 进度提示（快回滚 <5s 不出长文案） | 回滚执行；回滚前当前版本先存为快照（§7.4 第 5 条） |
| 5 | 回滚完成 | 浮层 + 消息流双落位 §7.5「回滚完成」原文：「已经回到之前的版本了，一切都在。要继续的话随时告诉我。」 | — |
| 6 | 观察时间轴变化 | 「当前版本」标记移到所选旧版本；原 15:24/15:23 两项保留但徽章变「存档」，**不出现在主干之外**（线性说明区：「回到过去后继续改，时间线接着往前走，不会分叉」） | 快照管理器线性策略（§7.4 第 6 条） |
| 7 | 继续对话修改 | 时间轴继续追加新条目；「存档」项永久可查但不参与当前版本 | — |

**设计要点**：回滚按钮仅出现在弹窗确认后执行；「存档」概念用徽章+一句话解释，绝不出现「分支/merge」词汇；用户无手动建快照入口（§7.4 第 7 条，遗留 L1 已移交需求侧）。

## 6. 旅程共性规则

| 规则 | 内容 | 依据 |
|------|------|------|
| 单一向导 | 所有旅程中用户只见「向导」一人格；角色切换零感知 | PRD §4.2 |
| 你帮我决定 | P1 门选择与 P2 每道选择题必附该选项 | PRD §7.6 |
| 5 秒规则 | 任何 >5s 操作进入进度提示阈值体系（见 interaction-spec §5） | PRD §7.5 |
| 文案即契约 | 五条心理防御文案逐字使用，不得改写（见 interaction-spec §4） | PRD §7.5 |
| 快照时机 | 初版生成时／用户确认修改前后／模式转换时／异常回滚前 | PRD §7.4 第 2 条 |
| 确认即预览 | 一切「确认」都以看得见的样子（原型/预览）为准，不以文档为准 | PRD §7.1/§7.6 |
