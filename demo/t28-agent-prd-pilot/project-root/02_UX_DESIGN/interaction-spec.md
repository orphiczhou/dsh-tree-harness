# 交互规格（Interaction Spec）：动效 / 过渡 / 状态与心理防御文案落位

> 文档编号：UX-05 | 隶属：02_UX_DESIGN | 依据：PRD §7.5（文案全量保留）、§7.3 点选纠错、§7.4 线性回滚、§2.4 恐惧点
> 版本：v1.0 | 日期：2026-11-15 | 角色：UI/UX顾问（t28a-W3-ux）
> 约束：§4 的五条文案为 **PRD 原文逐字保留**，实现与后续改版不得增删一字。

## 1. 动效总原则

1. **安全感优先**：动效慢而稳（200–300ms 为主），禁止弹跳过猛、闪烁、抖动；一切「突然出现」都要淡入。
2. **动效只用于三类事**：元素出现/消失、状态确认（选中/完成）、等待陪伴（呼吸）。
3. **陪伴优先于炫技**：等待场景用呼吸与文案，不用旋转 loading 圈（旋转圈 = 「机器在卡住」的恐惧联想）。
4. `prefers-reduced-motion: reduce` 时：全部动效时长置 0ms（直接切换），文案落位不变。

## 2. 动效/过渡规范表

| 名称 | 触发 | 时长 / 缓动 | 规格 |
|------|------|------------|------|
| 页面进入 | P0→P1→P2 等页切换 | 240ms ease-out | 整页淡入 + 上移 8px |
| 页面离开 | 同上 | 120ms ease-in | 淡出（无位移，避免方向感混乱） |
| 卡片选中 | 点选择卡 | 150ms ease-out | 描边变绿；对勾徽章 200ms `cubic-bezier(.34,1.56,.64,1)` 弹性放大 |
| 卡片悬停 | 鼠标悬停 | 120ms | 上浮 2px + 阴影加深（触屏无此态） |
| 消息出现 | 新气泡入流 | 220ms ease-out | 淡入 + 上移 6px；消息流平滑滚至最新 |
| 标注气泡弹出 | 点选元素 | 200ms ease-out | 从点击点上浮 6px 淡入；收起 150ms |
| 进度条呼吸 | 等待中 | 2.4s 循环 ease-in-out | 圆点透明度 0.5↔1；轨道填充匀速前进不回退 |
| 进度完成 | 任务结束 | 300ms | 打勾徽章弹性出现；轨道满格定格 600ms 后整条淡出 |
| 快照提示条 | 自动备份完成 | 滑入 260ms → 停留 4s → 滑出 200ms | 右下角（桌面端）上缘（窄屏）；可手动关 |
| 回滚过渡 | 确认回滚执行 | 300ms | 全屏轻纱（米白 40%）盖下 → 内容切换 → 淡出 |
| 预览刷新 | 修改完成 | 320ms | 旧视图淡出与新视图淡入交叉（自动刷新，§7.3 行为 5） |
| 弹窗出现 | 确认弹窗 | 180ms ease-out | 遮罩淡入 + 卡片缩放 0.96→1 |
| 徽章变档 | 回滚后「存档」 | 200ms | 颜色交叉淡变 |

## 3. 关键组件状态变化规则

| 组件 | 状态机 |
|------|--------|
| 选择卡 | 未选 →（点）选中（单选互斥，旧选中退回未选）→ 确认条出现；一旦进入对话不可回改本题（可再发新题修正） |
| 修改意图卡 | 记录（灰点）→ 执行中（呼吸绿点，禁止再点「不改了」）→ 已完成（对勾）／已撤销（划线置灰） |
| 进度提示条 | 隐藏 →（⏱≥5s）出现-等待中文案 →（≥40s）加阶段小字 →（≥90s）操作超时文案+催我 → 完成打勾 → 按场景落成功/回滚文案 → 淡出 |
| 快照时间轴项 | 常规 →（回滚确认中）高亮描边 →（执行）禁点 →（完成）目标项挂「当前版本」徽章，其后各项变「存档」 |
| 预览元素 | 常规 →（悬停）虚线高亮 →（点开气泡）实线描边+气泡锚定 →（开始改）整屏轻纱+呼吸 →（完成）刷新后该元素绿色细描边 1.5s 后消退 |
| 输入框 | 空（占位语）→ 聚焦（绿描边）→ 有内容（发送钮点亮）→ 发送中禁用 0.8s 防连发 |

## 4. 心理防御文案全量落位（PRD §7.5 原文逐字保留）

> ⚠ 实现契约：以下五条文案**一字不改**。出现位置、触发条件、呈现方式如下表；冲突时以原文为准。

### 4.1 文案原文（逐字）

1. **等待中**
   > 我正在帮你生成可运行的版本，这个过程只发生在安全环境里，不会影响你的电脑文件。
2. **修改成功**
   > 改好了，你看看效果？不满意随时告诉我。
3. **修改失败**
   > 刚才的修改没有成功，我已经帮你回到上一个正常版本，你的内容没有丢失。我们换个思路试试？
4. **回滚完成**
   > 已经回到之前的版本了，一切都在。要继续的话随时告诉我。
5. **操作超时**
   > 这次操作花了比预期更长的时间，我还在处理中。如果等太久，你可以催我。

### 4.2 落位表

| # | 场景 | 触发条件 | 出现位置 | 形态 | 停留 | 交互 |
|---|------|---------|---------|------|------|------|
| 1 | 等待中 | 任一 >5s 操作进入等待（生成原型/编码/修改/回滚长动作），⏱ 第 5 秒起 | P2 消息流内嵌进度提示条主文案位；P3 开始改时同 | 白卡进度条 + 🧭 图标 | 任务完成前常驻 | 不可关闭；下方可切去时间轴/设置 |
| 2 | 修改成功 | 修改流程完成且预览已刷新 | P3 预览上方浮层 + P2 消息流气泡（双落位） | ✅ 图标 + 原文 | 浮层 4s；气泡永久 | 浮层可关；气泡附「看看效果 →」 |
| 3 | 修改失败 | 自修复 3 次失败且已回滚到上一正常版本（PRD §6.3 熔断） | P2 消息流气泡（不弹全屏） | 🛟 图标 + 原文 | 永久 | 附按钮「换个思路」/「先看看时间轴」 |
| 4 | 回滚完成 | 用户确认回滚执行完毕 | P4 浮层 + P2 消息流气泡（双落位） | ⏮ 图标 + 原文 | 浮层 4s；气泡永久 | 浮层可关 |
| 5 | 操作超时 | 同一等待持续 ≥90s | 进度提示条**主文案位原文替换**（等待中→操作超时） | ⏱ 图标 + 原文 + 「催我」按钮 | 替换后常驻至完成 | 「催我」→ 温柔回应「收到！我加把劲。」（埋点#10） |

**文案使用禁令**：不得在上述位置追加技术状态词（如「重试中/重连/解析响应」）；不得把「修改失败」渲染成红色大弹窗（用 🛟 气泡 + 温和珊瑚红细线，design-system §2.2）。

## 5. 超过 5 秒显示进度提示规则（PRD §7.5）

| 时间轴 | 界面表现 |
|--------|---------|
| t = 0–5s | 触发按钮转「正在做…」禁点态；**不出现**进度条（短操作不制造等待感） |
| t ≥ 5s | 出现进度提示条：主文案 = §7.5「等待中」原文；第二行阶段小字（如「正在画页面样子」）；轨道呼吸前进 |
| t ≥ 40s | 阶段小字推进（「第 3 步：检查质量，快好了」）；主文案不变 |
| t ≥ 90s | 主文案替换为 §7.5「操作超时」原文 +「催我」按钮出现（仍保留阶段小字） |
| 完成 | 打勾动画 → 文案按场景切换：编码交付 =「修改成功」；回滚 =「回滚完成」（双落位见 §4.2） |

补充规则：
- 阶段小字必须是人话步骤（画样子 / 改你点的地方 / 检查质量），禁止出现「构建/编译/部署」。
- 「催我」点击后按钮转灰 30s 防连点，并记录埋点#10。
- 多个任务并行等待时只显示一条合并进度（「正在做 2 件事：改按钮、检查页面」），不叠加多条。
- 快消型编码全程（可能数分钟）按同一阈值体系循环：40s 小字按 5 步推进循环，90s 出「催我」后每 3 分钟重复一次超时文案，直到完成。

## 6. 点选纠错交互细则（PRD §7.3）

状态机：`浏览 → 高亮可点 → 选中·气泡 → 意图入列 → 开始改 → 修改中 → 刷新 → 反馈`

1. **浏览**：进入预览即开启可点模式；引导条 C14 首次出现。
2. **高亮**：悬停元素虚线描边（触屏：长按 300ms 进入点选并高亮）。
3. **选中**：点击 → 元素实线描边 + 标注气泡锚定其旁（自动避开屏幕边缘）。
4. **意图**：选快选 chip 或输入一句话 →「先记下来」→ 气泡收起、C12 卡入「想改的地方」清单；**此步不触发任何修改**。
5. **撤销**：单条「不改了」即时移除（已执行条目除外）；点空白处关闭气泡不产生记录。
6. **开始改**：点「让向导开始改」→ 先落快照（提示条 C9「修改前自动备份」）→ 进度条（§5 阈值）。
7. **修改中**：清单对应项转呼吸绿点；「开始改」禁点；用户可离开预览，进度在 P2 继续。
8. **刷新**：完成 → 预览交叉淡入刷新（§7.3 行为 5）→「修改成功」文案双落位 → 目标元素绿色细描边 1.5s 指示变化点。
9. **反馈循环**：不满意继续点选（回到第 2 步）；全部满意 →「整体都还行，去确认」回 P2。
10. 失败支路：同 §4.2 #3「修改失败」原文；清单保留、意图卡回「记录」态可再改说法。

## 7. 回滚与快照交互细则（PRD §7.4）

1. **快照全自动**：无任何「保存版本」按钮；页首固定说明「快照由我自动管理，你不用记着点保存」。
2. **触发时机（界面必留痕）**：初版生成、用户确认修改前后、模式转换、异常回滚前 —— 每次以 C9 提示条告知（一句话人话描述）。
3. **一键回滚**：仅时间轴项「回到这里」→ 必须 C13 二次确认（含「现在这份也会存起来，不会丢」）。
4. **线性呈现**：时间轴单列直线；回滚后目标项挂「当前版本」，其后项挂「存档」徽章且**不再显示「回到这里」**（避免制造平行分支感）；主干上方固定一句线性说明：「回到过去后继续改，时间线接着往前走，不会分叉。」
5. **回滚反馈**：完成后 §4.2 #4「回滚完成」原文双落位；时间轴徽章变档（§3）。
6. **异常自动回滚**（用户未发起）：流程同 §4.2 #3，消息流插入手写风格气泡说明，并附「先看看时间轴」快捷入口。
7. **存档可见性**：存档项可点展开（查看当时描述与时间），不提供「恢复到存档」以外的操作；如需以存档为基线继续，等价于再执行一次回滚（同一确认流程）。

## 8. 空状态与首次引导

| 场景 | 表现 |
|------|------|
| 新项目时间轴为空 | C16：🗓️「还没有足迹。等我们开始做点东西，这里就会有记录。」 |
| 想改清单为空 | 预览区仅显示引导条，不渲染空清单面板 |
| 首次进入预览 | C14 引导条，完成一次点选后永收 |
| 首次回滚前 | C13 弹窗正文自动多一句「（第一次回滚？放心，我们演示着来）」——仅文案差异 |

## 9. 禁止出现的界面元素（负面清单）

- 任何源码/控制台/日志窗口；百分比进度数字；红色全屏错误弹窗；「分支图/版本树」可视化；多标签页技术面板；进度里的英文技术词；动画中的旋转 loading 圈（等待场景）。
