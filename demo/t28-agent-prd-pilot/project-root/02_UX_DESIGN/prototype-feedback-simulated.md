# 模拟原型反馈纪要（自主模拟用户 · 3 轮）

> 文档编号：UX-01 | 隶属：02_UX_DESIGN | 依据：PRD §7.1/§7.5/§7.6、§2.4；输入裁决 3「自主模拟用户」
> 版本：v1.0 | 日期：2026-11-15 | 角色：UI/UX顾问（t28a-W3-ux）

---

## 1. 背景与方法

### 1.1 背景与依据

- **裁决 3「自主模拟用户」**：树内由 UI/UX 顾问会话自主模拟零基础用户画像，完成多轮原型评审挖掘，全程零打断、不请求真人介入。
- **被评审对象**：本目录 `wireframes/` 下 4 个可交互 HTML 原型（模式门 / 聊天主界面 / 原型预览·点选纠错 / 时间轴·回滚）。
- **评审视角对齐 PRD §2.4 六大恐惧点**：怕看到代码、怕搞坏东西、怕隐私泄露、怕AI做的不对、怕操作太复杂、怕等待焦虑。

### 1.2 方法

每轮按固定三段式执行并留痕：

1. **展示原型要点**：向模拟用户呈现本轮原型与关键交互；
2. **模拟用户反馈**：以画像口音回答两个固定问题——「哪里看不懂？」「怕搞坏什么？」；
3. **设计调整记录**：逐条给出调整动作与落位文档（编号可追溯）。

### 1.3 模拟用户画像（3 人）

| 编号 | 画像 | 背景 | 主要恐惧 |
|------|------|------|---------|
| PU-01 | 林晓雨，20 岁，历史系大二 | 零基础文科生，只用手机 App，从未接触编程 | 怕看到代码、怕把电脑弄坏 |
| PU-02 | 老周，42 岁，单位行政文员 | 天天用办公软件，谨慎型，不敢乱点 | 怕点错无法撤销、怕隐私泄露 |
| PU-03 | 陈思远，21 岁，商学院大三 | 做过问卷星表单，懂点概念但不写代码 | 怕AI做的不对、怕等半天没结果 |

## 2. 第一轮：模式门 + 聊天主界面

**展示原型**：`page-mode-gate.prototype.html`、`page-chat-main.prototype.html`

### 2.1 展示要点

- 启动后只有两张「门」卡片：快速做一个能用的（快消型）／长期慢慢打磨（长期迭代型），加一个「你帮我决定」入口；
- 进入后是唯一主界面：聊天。问题以卡片单选出现，每张卡都可不选而改用「你帮我决定」；
- 等待超过 5 秒会出现一条进度提示，写着安抚文案。

### 2.2 模拟用户反馈

| 用户 | 原话（模拟） | 归类 |
|------|-------------|------|
| PU-01 林晓雨 | 「快消型……这词我第一次听，像速食面吗？我不确定哪个适合我。」 | 看不懂 |
| PU-01 林晓雨 | 「如果我选错了会怎么样？会不会整个项目就废了？」 | 怕搞坏 |
| PU-02 老周 | 「两张卡片上那个小标签（快消型/长期迭代型）我不认识，但下面的大字我懂。」 | 看不懂 |
| PU-02 老周 | 「它问我的话，会不会偷偷记录发到网上？我说的都是工作上的事。」 | 怕隐私 |
| PU-03 陈思远 | 「只让我选卡片很舒服，但有时候我想补充一句自己的话，光点卡片说不清楚。」 | 操作受限 |
| PU-03 陈思远 | 「进度条写的那句话不错，但我不知道它到底做到哪一步了。」 | 等待焦虑 |

### 2.3 设计调整记录

| 编号 | 调整动作 | 落位文档 |
|------|---------|---------|
| A1-01 | 两道门卡片**大标题用生活语言**（「快速做一个能用的」「长期慢慢打磨」），术语「快消型/长期迭代型」降级为小徽章 | sitemap P1、wireframes page-mode-gate |
| A1-02 | 门卡片说明改为「选错了也没关系，以后都能改」承诺 + 设置页提供模式切换入口（快消型完成后可升级长期型，对齐 PRD §3.3） | user-flows UF-01、sitemap P5 |
| A1-03 | 卡片单选题下方**常驻自由输入框**：可点卡，也可打字补充，两者不互斥（PRD §7.6「偏好卡片选择」是偏好不是唯一） | wireframes page-chat-main、design-system C5/C7 |
| A1-04 | 进度提示条增加**阶段小字**（如「第 2 步：画页面样子」），安抚文案（§7.5 等待中）保持主位 | interaction-spec §4/§5、design-system C8 |
| A1-05 | 隐私安心位固定在启动页与聊天页底部：「你的内容保存在你自己的电脑上。」（PRD §1.3 本地运行 + §12.2 脱敏） | sitemap §6 全局元素、design-system §7 |

## 3. 第二轮：原型预览 + 点选纠错

**展示原型**：`page-preview-fix.prototype.html`

### 3.1 展示要点

- 预览区直接展示做出来的页面样子（模拟数据），这是用户最主要的确认方式（PRD §7.1）；
- 对不满意的地方**直接点它**，会弹出小气泡记下「你想改哪里」，攒起来一起改；
- 改动前自动存快照，改完预览自动刷新。

### 3.2 模拟用户反馈

| 用户 | 原话（模拟） | 归类 |
|------|-------------|------|
| PU-01 林晓雨 | 「我不知道原来可以点，页面看起来就是一张图啊。」 | 看不懂 |
| PU-01 林晓雨 | 「我点了它会不会马上就改了？我还没想好呢。」 | 怕搞坏 |
| PU-02 老周 | 「万一我点错了地方，会不会把别的地方弄坏？」 | 怕搞坏 |
| PU-02 老周 | 「气泡里那几个快选（换颜色/改文字）挺好，我不用组织语言。」 | 好评 |
| PU-03 陈思远 | 「改完之后我想看看改之前长什么样，能不能对比？」 | 看不懂 |
| PU-03 陈思远 | 「『转换成修改意图』这种提示词太正式了，像在签合同。」 | 文案生硬 |

### 3.3 设计调整记录

| 编号 | 调整动作 | 落位文档 |
|------|---------|---------|
| A2-01 | 预览区顶部加**首次引导条**：「看哪里不顺眼？直接点它试试。」并且可点的元素悬停时有虚线高亮，让「可点」可见 | interaction-spec §6、wireframes page-preview-fix |
| A2-02 | 气泡明示**两段式**：点选只「先记下来」，出现按钮「让向导开始改」才真正动手——用户始终握有扳机 | interaction-spec §6 状态机、user-flows UF-04 |
| A2-03 | 点错可随时「算了，不改了」单条撤销；每次改动前快照提示条出现，失败可一键回旧版本 | design-system C11/C12、interaction-spec §4 修改失败 |
| A2-04 | 「转换成修改意图」改写为**「我把你想改的地方记下来了」**；清单标题用「想改的地方」 | 全局文案规范 design-system §7 |
| A2-05 | 改前/改后对比归入时间轴（点快照可看当时的页面样子），预览区不堆并排对比，保持简单；记为增强项候选 | sitemap P4 备注、§7 遗留 |

## 4. 第三轮：时间轴 + 回滚（含异常回滚体验）

**展示原型**：`page-timeline-rollback.prototype.html` + 异常流程演示（修改失败→自动回滚）

### 4.1 展示要点

- 每次重要变化前后自动存「快照」，列表里是时间 + 一句人话描述；
- 一键回到任意旧版本；回到过去之后现在这份也不会丢；
- 出问题（改 3 次还不成功）系统自己回到上一个正常版本，并用安抚文案告诉你。

### 4.2 模拟用户反馈

| 用户 | 原话（模拟） | 归类 |
|------|-------------|------|
| PU-01 林晓雨 | 「『快照』是拍照的意思吗？是我手机的相册那种吗？」 | 看不懂 |
| PU-01 林晓雨 | 「回去以后，我现在做的新的东西会不见吗？」 | 怕搞坏 |
| PU-02 老周 | 「『回到这里』这个按钮有点吓人，我会怕手一抖点错。」 | 怕搞坏 |
| PU-02 老周 | 「失败那段文案很好，告诉我『内容没有丢失』，我心里就定了。」 | 好评（§7.5 原文有效） |
| PU-03 陈思远 | 「我不明白回到旧版本之后再改，会不会出现两个平行版本？谁是最新的？」 | 看不懂 |
| PU-03 陈思远 | 「我想自己手动存一个『完美版』，以后不管怎么改都有底。」 | 操作诉求 |

### 4.3 设计调整记录

| 编号 | 调整动作 | 落位文档 |
|------|---------|---------|
| A3-01 | 「快照」在界面上以**「自动备份」为主称呼、快照为副词**（首次出现写「自动备份（快照）」），时间轴页首行给一句比喻：「像游戏存档一样」 | 全局、wireframes page-timeline-rollback |
| A3-02 | 回滚按钮加**二次确认弹窗**，弹窗内原文承诺「现在这份也会存起来，不会丢」（对齐 PRD §7.4 第 5 条），按钮措辞用「对，回到那里／再想想」 | interaction-spec §7、design-system C13 |
| A3-03 | 线性回滚用**一条直线时间轴**呈现，回到旧版后继续修改 = 时间线继续往前走；旧版之后的记录保留但标「存档」徽章；**全程不出现「分支」一词**（PRD §7.4） | wireframes page-timeline-rollback、interaction-spec §7 |
| A3-04 | 回滚完成提示必须原样使用 §7.5「回滚完成」文案，且时间轴刷新动画演示「当前版本」标记移动 | interaction-spec §4 |
| A3-05 | 「手动存档」诉求与 PRD §7.4 第 7 条（用户不可手动创建快照）冲突——**保留系统约束**，界面回应：「快照由我自动管理，你不用记着点保存」；记为遗留问题提交需求分析师评估（见 §5） | §6 遗留问题 L1 |

## 6. 遗留问题（移交需求分析师 W2 评估）

| L3 | 语音输入降低打字门槛 | PU-02 使用场景推演 | PRD 未定义，建议远期；本期以卡片选择+短输入降低门槛 |

## 7. 结论

三轮模拟反馈共产生 **15 条设计调整（A1-01 ~ A3-05）**，全部落实到 sitemap / user-flows / design-system / interaction-spec / 4 个原型中；另有 3 条遗留问题移交需求侧。核心共识：**「先记录、后执行」「随时可回、不丢东西」「说人话、少术语」**三条原则贯穿全部界面。
