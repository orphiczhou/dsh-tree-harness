## 1. 裁决总览

### 1.1 项目特征输入

| 特征维度 | 本项目取值 | 对配置的影响 |
|---|---|---|
| 文档模式 | 长期迭代型全量（用户裁决 #2） | 架构师（P1）、代码审查员（P6）**必选**（§4.4 激活条件）；工程/文档约束全量 H1–H8 |
| 产品形态 | Electron 桌面应用（ADR-01），Proma fork | 有 UI 需求 → 前端（P2）；Main Process 承载 M1–M9 运行时与 E-01…E-30 端点 → 后端（P3） |
| 项目规模 | 16 个 Sprint / 32 周 / 24 项功能 / M0–M9 十个模块 | 多角色并行流水线 → 项目经理（P8）；三平台打包与 CI → DevOps（P7） |
| 验收机制 | GWT 89 场景为编码前验收契约，全量通过=交付合格 | 测试工程师（P5）**必选**（§4.4：所有项目必选） |
| 模板匹配 | 按 §11.2 六类模板判定：**不采用**「桌面工具（全栈+测试）」模板 | 桌面工具模板面向 PyQt/Tauri 小型效率工具；本项目为长期迭代型大型多 Sprint 项目，按规模与文档模式套用 **Web全栈模板的长期迭代型配置**（§11.5：架构师+前端+后端+测试+代码审查员）并按需追加 DevOps/PM |

### 1.2 激活裁决

| # | 角色 | 池编号 | 激活 | 裁决依据 |
|---|---|---|---|---|
| 1 | 架构师 | P1 | ✅ **激活** | 长期迭代型必选（§4.4）；PlantUML 主约束（H3/H8）需要常设结构守门角色 |
| 2 | 前端开发 | P2 | ✅ **激活** | 有 UI 需求（§4.4）：M0 Renderer 全部页面（P0–P6 用户前台 + R1–R5 研究区） |
| 3 | 后端开发 | P3 | ✅ **激活** | 有后端需求（§4.4）：M1–M9 运行时引擎与 E-01…E-30 端点 |
| 4 | 全栈开发 | P4 | ❌ **不激活** | §4.4 激活条件为「快消型或小型项目」，本项目不满足；详见 §3 |
| 5 | 测试工程师（测试Agent） | P5 | ✅ **激活** | 所有项目必选（§4.4）；GWT 收口机制（F-15）执行者 |
| 6 | 代码审查员 | P6 | ✅ **激活** | 长期迭代型必选（§4.4）；代码质量/安全/合规审查（§6.2 流水线步骤 3） |
| 7 | DevOps工程师 | P7 | ✅ **激活** | 需要部署（§4.4）：electron-builder 三平台打包、CI/CD、预览静态服务与本地执行沙箱环境管理 |
| 8 | 项目经理 | P8 | ✅ **激活** | 大型多 Sprint 项目（§4.4）：16 Sprint 进度追踪、阻塞协调、里程碑收口 |

**结论：激活 7 角色（P1/P2/P3/P5/P6/P7/P8），不激活 1 角色（P4 全栈开发）。** 与 §11.5 模板推荐配置（架构师+前端+后端+测试+审查员）对齐，并按本项目部署与多 Sprint 特征追加 P7/P8——追加理由可追溯到 §4.4 激活条件，非临时扩编。

## 2. 激活角色卡片（职责边界 / 交付物 / 上下游交接 / 模型策略）

### P1 架构师（长期迭代型必选）

| 维度 | 内容 |
|---|---|

| **交付物** | Sprint 规约审核意见（开工许可）；代码结构 ≡ PlantUML 比对报告；接口变更记录（后台文档）；规约争议裁决记录 |
| **上下游交接** | 上游 → 从工程经理（Sprint 工作包，本配置与 `sprint-plan.md`）、架构设计师 G3 的架构基线（`03_ARCHITECTURE/`+`04_API_SPEC/`）拿输入；下游 → 给前端 P2 / 后端 P3 已审核规约与开工许可；给裁判（M5）结构比对材料；给 P6 审查基线（结构合规 checklist） |
| **模型策略建议** | **长上下文 SOTA**（`architecture.md` §3.3：「编程各角色 P1–P8 代码模型为主；架构师角色用长上下文」；§4.4 激活条件=长期迭代型必选）——需通读全量架构基线与多模块代码做结构比对，长上下文为硬需求 |

## 3. 未激活角色与理由（内部决策记录，对用户透明不呈现）

| 角色 | 池编号 | 未激活结论 | 理由 |
|---|---|---|---|
| 全栈开发 | P4 | ❌ 本项目不激活 | ①**激活条件不满足**：§4.4 明确 P4 适用于「快消型或小型项目」，本项目为长期迭代型 16-Sprint 大型项目；②**职责已被覆盖**：§11.5 长期迭代型推荐配置为「架构师+前端+后端+测试+代码审查员」，前后端由 P2/P3 按 §11.5 协作流程并行（前端 Mock 不阻塞后端），全栈位冗余；③**边界清晰性**：若同时激活 P4，其交付与 P2/P3 在 Reviewer 审查责任链上边界模糊，违背「职责边界明确」的配置原则（H6）；④**非废弃声明**：P4 仍是平台角色池成员——本项目 S11 交付「角色池全激活」平台资产时，P4 的 System Prompt 与模型配置照常入库（快消型管线 F-10/F-13 对用户的快消项目会激活它）；**本裁决仅指本项目自身开发团队不激活，不代表平台不支持该角色** |

> 一句话结论：**7/8 激活，唯一裁撤的是与 P2+P3 并行流水线职责重叠、且激活条件（快消/小型项目）不满足的全栈位。**
