## 1. 拆分原则（INVEST 自检）

| 原则 | 本拆分如何满足 |
|------|---------------|
| **I**ndependent（独立） | 每条故事只描述一个 F-xx 的主行为，可独立交付与验收；跨功能联动（如快照）在验收要点中以"联动 F-xx"标注，不并入故事主体 |
| **N**egotiable（可协商） | 故事只锁定行为结果，不锁实现方式；细节在需求对话中可与用户协商（如原型样式、确认点数量） |
| **V**aluable（有价值） | 每条故事从零基础用户或研究者视角陈述可感知的价值 |
| **E**stimable（可估算） | 每条故事关联的 F-xx 已有 GWT 要点句验收标准，可据此估算工作量 |
| **S**mall（小） | 一条故事 ≤ 一个 F-xx 的核心场景组（正常+关键异常） |
| **T**estable（可测试） | 每条故事附验收标准，均可用 GWT 要点句转写为可执行测试（供 W4 对账） |

**覆盖策略**：P0 功能（F-01/02/03/05/06/08/09/10/13/15/16/19，共 12 项）每项至少 1 条故事；P1/P2 抽代表性 10 项（F-04/07/11/12/14/17/18/22/23 + 研究侧 F-20/21）；F-24（Figma 远期可选）不拆故事，理由见 §4 覆盖矩阵。

## 3. 用户故事详情

### 3.1 P0（快消型主轴，全量覆盖）

#### US-01 开门二选一（↔ F-01，P0）

- **故事**：作为**零基础用户**，我想在开始时明确选择"快速做个小工具"还是"做长期项目"，以便我不必担心选错路。
- **验收标准（GWT 要点）**：
  - Given 新建项目，When 未选择模式，Then 只见两张模式卡片，无法进入其他界面。
  - Given 卡片说明可见，When 阅读快消型说明，Then 能看到"以后可升级为长期项目"。
  - Given 项目中途重新打开，When 恢复会话，Then 保持原模式且不再询问。

#### US-02 用卡片问答把想法说清楚（↔ F-02，P0）

- **故事**：作为**零基础用户**，我想通过点选卡片回答少量问题来描述我的想法，以便不用打长篇文字也不用懂术语。
- **验收标准（GWT 要点）**：
  - Given 我说出想法，When 向导提问，Then 每轮 3–5 个问题且每题有点选卡片和「你帮我决定」。
  - Given 我补充"我想确认一下如果……"，When 方案定稿，Then 这个关切变成一条被测试的验收场景。
  - Given 我随时想回顾，When 打开需求清单，Then 看到生活化的已确认要点。

#### US-03 得到一份看得懂的方案单（↔ F-03，P0）

- **故事**：作为**零基础用户**，我想在开工前看到一页纸的方案单（给谁用、做什么、验收什么），以便确认我们没有理解偏差。
- **验收标准（GWT 要点）**：
  - Given 需求对话收敛，When 生成精简方案单，Then 含项目名称、目标用户、功能清单、验收标准四项。
  - Given 我阅读方案单，When 读开头，Then 不懂技术也能明白要做什么。

#### US-04 双击就能点的页面样板（↔ F-05，P0）

- **故事**：作为**零基础用户**，我想在浏览器里直接点开一个能按、能跳的页面样板，以便亲眼确认"是不是我想要的"。
- **验收标准（GWT 要点）**：
  - Given 方案单确认，When 生成样板，Then 单文件 HTML 双击即可打开、可点击跳转、带模拟数据。
  - Given 应用内预览，When 查看，Then 不出现任何代码。

#### US-05 AI 自己先检查页面好不好用（↔ F-06，P0）

- **故事**：作为**零基础用户**，我想让系统在给我看之前先用"眼睛"检查页面布局，以便少来回折腾我。
- **验收标准（GWT 要点）**：
  - Given 样板生成，When 自动审查完成，Then 明显布局问题已被修正再进入预览。
  - Given 我截图圈出问题发回，When 系统接收，Then 它用一句人话复述理解并开始修改。

#### US-06 改坏了随时退回旧版本（↔ F-08，P0）

- **故事**：作为**零基础用户**，我想随时回到之前某个正常的版本，以便大胆尝试而不怕搞坏东西。
- **验收标准（GWT 要点）**：
  - Given 关键节点（初版/确认前后/转换/回滚前），When 到达，Then 自动存档并带人话说明。
  - Given 我在历史列表点"回到这个版本"，When 回滚完成，Then 先保存当前版本再恢复旧版本，两者都不丢。
  - Given 回滚后继续修改，When 查看时间轴，Then 只有一条时间线，没有"分支"概念。

#### US-07 只跟一个"向导"说话（↔ F-09，P0）

- **故事**：作为**零基础用户**，我想始终和同一个"向导"对话，以便不用学习多角色界面、不怕说过的东西被忘掉。
- **验收标准（GWT 要点）**：
  - Given 任意阶段，When 我发言，Then 界面只有一个"向导"，没有角色切换器。
  - Given 阶段推进，When 内部换人，Then 我无感知且上下文连续。

#### US-08 点"开始做"就等成品（↔ F-10，P0）

- **故事**：作为**零基础用户**，我想点一下"开始做"就等能用的成品，以便不被技术问题打断。
- **验收标准（GWT 要点）**：
  - Given 方案与样板确认，When 点击开始，Then 全程只见人话进度，无技术提问。
  - Given 测试全过，When 交付，Then 拿到可运行版本并受邀试用反馈。

#### US-09 不用管背后是谁在干活（↔ F-13，P0）

- **故事**：作为**零基础用户**，我不想看到或配置任何"AI 团队成员"，以便界面保持一个聊天框的简单。
- **验收标准（GWT 要点）**：
  - Given 进入编码阶段，When 团队组建，Then 界面无任何角色配置信息。
  - Given 团队协作发生，When 交接，Then 通过内部文件体系完成且对我不可见。

#### US-10 交付前所有用法都试过一遍（↔ F-15，P0）

- **故事**：作为**零基础用户**，我想在拿到成品前知道"每种用法都测过且通过"，以便放心使用。
- **验收标准（GWT 要点）**：
  - Given 方案定稿，When 生成测试，Then 每个功能至少一个场景且含正常/边界/异常。
  - Given 全部通过，When 收口，Then 给我看人话版通过报告。
  - Given 有场景未过，When 判定，Then 不交付，退回修复。

#### US-11 文档不全就先不让开工（↔ F-16，P0）

- **故事**：作为**零基础用户**，我想让系统在方案不完整时先拦下来补全，以便不会拿到做一半的东西。
- **验收标准（GWT 要点）**：
  - Given 方案缺"给谁用/功能/验收"任一项，When 提交进入下一步，Then 被退回并用人话说明缺什么。
  - Given 快消型同一文档两次退回仍不过，When 判定，Then 提示需要人工介入。

#### US-12 等待和出错都有人话安慰（↔ F-19，P0）

- **故事**：作为**零基础用户**，我想在等待时看到安心的人话进度、在出错时听到"你的东西没丢"，以便不焦虑、不慌张。
- **验收标准（GWT 要点）**：
  - Given 任一操作超过 5 秒，When 等待中，Then 显示"安全环境、不影响你的电脑"类进度提示。
  - Given 失败/回滚/超时发生，When 播报，Then 使用指定安抚文案，无技术报错。

### 3.2 P1（长期迭代型与体系完善，代表性）

#### US-13 正式项目有全套规划文档（↔ F-04，P1）

- **故事**：作为**零基础用户**，当我想认真做一个长期项目时，我想要一套完整的方案和任务清单，以便每一步都有据可查。
- **验收标准（GWT 要点）**：
  - Given 长期型需求收敛，When 我签字确认，Then 产出完整 PRD 与用户故事文档。
  - Given 文档产出，When 校验，Then 每个功能有验收标准、编号唯一。

#### US-14 正式项目在关键节点问我意见（↔ F-11，P1）

- **故事**：作为**零基础用户**，我想在正式项目的设计方案和开发节奏两个节点被征求意见（或选"你帮我决定"），以便保留掌控感又不被频繁打扰。
- **验收标准（GWT 要点）**：
  - Given 文档未齐，When 请求开工，Then 不开工并列出缺项。
  - Given 方案与计划产出，When 确认，Then 生活化卡片提问且带「你帮我决定」。

#### US-15 一次性的小工具能"转正"（↔ F-12，P1）

- **故事**：作为**零基础用户**，我想把用着顺手的一次性小工具升级成正式项目继续加功能，而不必从头重做。
- **验收标准（GWT 要点）**：
  - Given 快消项目进行中/已完成，When 我选升级，Then 先收到"建议先完成快消"提示，可坚持升级。
  - Given 升级完成，When 进入长期管线，Then 已有软件成为起点，缺失文档被补全，转换前后各存档一次。

#### US-16 指着界面说哪里不满意（↔ F-07，P1）

- **故事**：作为**零基础用户**，我想直接点着页面说"这里不行"，以便不用费劲打字描述。
- **验收标准（GWT 要点）**：
  - Given 预览区，When 我点击/框选元素并说期望，Then 系统捕获位置与上下文并生成修改指令。
  - Given 修改完成，When 预览刷新，Then 目标位置已按期望变化；大改动前已自动存档。

#### US-17 系统猜得到我要做哪类东西（↔ F-14，P1）

- **故事**：作为**零基础用户**，我想让系统听我说两句就明白这是网页、小工具还是要连设备的项目，以便不用自己选技术类别。
- **验收标准（GWT 要点）**：
  - Given 我的对话含类型线索，When 系统推断，Then 匹配模板且过程对我不可见。
  - Given 推断完成，When 确认，Then 用一句人话复述（"你想做的是一个网页小站"），允许我纠正。

#### US-18 修不好就退回好版本并说实话（↔ F-18，P1）

- **故事**：作为**零基础用户**，当 AI 改坏东西且修不好时，我想听到实话、回到好的版本、并有选择下一步的权利，以便始终掌控我的东西。
- **验收标准（GWT 要点）**：
  - Given 修复尝试最多 3 次，When 仍失败，Then 回滚到上一健康快照并播报"已回到上一个正常版本，你的内容没有丢失"。
  - Given 快消型，When 熔断后重试，Then 在后台换方案，不来反悔我的需求。
  - Given 长期型且设计约束不可实现，When 处置，Then 给我一份人话变更说明，等我确认再调整。

#### US-19 长期项目按小段节奏推进（↔ F-22，P1）

- **故事**：作为**零基础用户**，我想让长期项目按两三周一段的节奏交东西，以便每隔一段时间就能看到进展。
- **验收标准（GWT 要点）**：
  - Given 开工前，When 产出计划，Then 每段 ≤2 周且每段交付可运行增量。
  - Given 某版本发布，When 更新记录，Then 变更日志自动追加且历史可查。

#### US-20 换个时间继续做，AI 还记得（↔ F-23，P1）

- **故事**：作为**零基础用户**，我想隔几天回来继续项目时一切照旧，以便不用重新解释我是谁、做到哪了。
- **验收标准（GWT 要点）**：
  - Given 新会话接管，When 我回来，Then 需求、设计约束、进度完整，无需复述。
  - Given 角色交接，When 发生，Then 已确认结论不被悄悄更改。

#### US-23 文档质量有 AI 把关（↔ F-17，P1，研究者视角）

- **故事**：作为**研究者**，我想让裁判对文档做逻辑一致性、可测试性、完整性、可读性的 AI 评估，以便研究产出的文档质量可量化。
- **验收标准（GWT 要点）**：
  - Given 文档过硬约束，When 软约束评估，Then 四维度各出三档结论与理由。
  - Given 文档含未解释术语，When 可读性评估，Then 标记"建议改进"并指出位置。

### 3.3 P2（数据与科研，代表性）

#### US-21 全程行为被安静地记录（↔ F-20，P2）

- **故事**：作为**研究者**，我想让用户在平台里的对话与操作被无打扰地完整记录（脱敏），以便分析非专业人员驱动 AI 开发的行为范式。
- **验收标准（GWT 要点）**：
  - Given 任一交互事件，When 落库，Then 按事件清单逐项记录且用户界面零打扰。
  - Given 科研数据导出，When 检查，Then 不含真实业务内容。

#### US-22 后台看板出研究数据（↔ F-21，P2）

- **故事**：作为**研究者**，我想在后台看板看到效率、Token 分布、认知摩擦、合规趋势并能导出对比数据，以便支撑论文结论。
- **验收标准（GWT 要点）**：
  - Given 打开看板，When 查看任一视图，Then 可按项目类型筛选并导出。
  - Given A/B 实验运行，When 导出，Then 含对照组与实验组核心指标对比。
