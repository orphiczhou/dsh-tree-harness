## 5. DSH API / 环境事实（本轮血泪，勿再踩）

1. **客户端模块契约**：`window.__ModuleLoader__.load({id, factory})` 的 `factory` **必须 `return module.exports`**（插件对象含 `apply`），且**所有 DOM 副作用放在 `apply(ctx)` 里**；返回 `undefined` → 客户端启动冲突（整页加载失败，用户被迫禁用全部第三方插件）。
2. **客户端半热更会残留旧实例**：旧 `setInterval`/旧 DOM 节点不会自动销毁。对策（已实装）：`window.__metaLoopCtl` 令牌仲裁（只有最新实例可操作入口）+ `window.__metaLoopUi` 单例注册表（跨实例复用 DOM）。**遇到"两枚入口/落位来回跳"，先查这个**。
3. **`--dsh-frame-top-clearance` 在本环境异常大（反推 ≈2090px）**：任何 `top: calc((var(--dsh-frame-top-clearance) - 28px)/2)` 之类居中公式会把元素推到视口底边（y≈1032）。定位一律用固定值（菜单行 `top: 7px`）。
4. **`.dsh-td-switch` 有两枚**（浮动 + `.dsh-td-bar` 内变体），`document.querySelector` 取到的可能不是可见那枚；**要锚"承载入口的那枚"**（`entry.closest('.dsh-td-switch')`）。
5. **td-tweak 量出并发布 `--td-tweak-left`**（=窗体菜单右缘，本机 196px）——水平定位首选它，退化为 `menuRect().right + 12`；`[role="menubar"]` 在本环境常取不到（实测 0），别依赖。
6. **`subagents.startContinuable(spec)`**：`spec.provider` 是**会话生成机制名**（`spawn|fork`）；`signal` 必填；`request.parent` 必须是 ctx.agents 里的**活 Agent**（来源=工具调用 `exec.agent`）；模型路由在 `request.agentOptions{provider,model,reasoningEffort}`；返回 `{childId,messageId}`。
7. **运行中改模型/effort/权限 = 物理不可能**（启动时一次性 resolve）；唯一出路 = `cancel + 带 assignee 重派`（树引擎已支持，assignee 持久化在 leaf 上）。
8. **effort/温度在插件层读不到**：effort 只存在于请求头，温度在宿主链路根本没有字段——`self_spec` 已显式标注 `unavailable + 原因`，别假装能读。
9. **`plugin_manager set_bundle` 可热装载**（bundle 必须在自己 `package.json` 的 `dsh.bundle.patch` 里声明 rows + `cordis.patch.yml` 写 `insert`），返回 `application:"applied"`；新增包还需 profile `package.json` 的 `bundles` + `dependencies`（`link:`）+ 一次 `pnpm install`。
10. **工程纪律**：文件只用 write/edit（pwsh `Set-Content -Encoding utf8` 会带 BOM，**BOM 会让 ESM 直接语法错误**；本会话已踩一次并用 git checkout 恢复）；PowerShell 传 `node -e` 复杂脚本会被解析坏 → **写成文件再跑**；JSON 里避免出现 `*/`（块注释提前闭合，已踩）。
