### 暂缓 / 不做（沿用地图 §9.3 的结论）

- **npm 解冻**：不是代码任务，需所有者决策 + 凭据/CI 新攻击面 + 双源漂移 → 先过 `publishing.md` §4 六项条件。
- **大改 leaf 状态机**：动真源风险高 → 先做「派生展示」（地图 #10 列为 Wave 3）。
- **全量多语言**：zh/en 已覆盖主要用户；扩展收益低、断言维护成本高（地图 #13）。
- **自动修改用户 profile**：安装/重载必须保留人工确认；`tree_doctor` 只建议、不代改。
- **外部依赖/框架**：零 `@deepseek-ai/*` 依赖是离线测试与快速适配的核心优势，不引入。
- **只读树面板（地图 #12）**：价值高但成本高，列为 Wave 3+；若用户 GUI 迭代要做，按 W2.8 先写方案再实施。

## 3. 执行方式（沿用 tree 方法）

1. `tree_plan` 建 `wave2` 树，root DoD = 本计划 §1 全部退出条件；
2. 按文件/职责拆 leaf（2A 的 W2.1 与 W2.3/W2.6 若同改 `src/guards.js`/`engine.js` 需串行或分文件；2B/2C 独立）；
3. 每个 leaf：`tree_dispatch` 派发 → 自报 progress → `tree_report done` → Lead `tree_verify`（command/artifact 策略）→ 全量测试 → Lead 统一 commit；
4. **发布门禁不降级**：任何包内容变化必须 bump；`release-plugin` 19/19 SHA；真机 E2E 三断言 + 文档链接/表格检查；
5. 文档按 [docs/README.md](../README.md) 规则归档，新增/移动文档更新索引。

## 4. 风险与依赖

| 风险 | 应对 |
|---|---|
| rc.2 asar fixture 随 DSH 版本漂移 | 记录 fixture 来源/校验和；缺 fixture 报明确错误，不算代码失败（地图 #5） |
| root 会话 id 归一化可能影响子会话语义 | 只归一化「根/父会话」比较层，不动 leaf owner 存储；负例 + 真机回归（W2.6） |
| 真机 E2E 需要真实会话/配额，可能 429 | 发布前由人触发；失败保留会话 id 与解码结果；CI 不跑真机（推荐 C） |
| GUI 迭代持续进行，文档易过期 | W2.8 单一 UI 文档 + 每次改动同 PR 更新；`agent.md` 决策日志记录方向变化 |
| 热重载读半写文件导致宿主崩溃 | 改宿主半前 disable bundle，或 `.tmp` 原子写；见 `agent.md`「热重载安全」 |
