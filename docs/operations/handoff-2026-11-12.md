## 5. 发布流程（摘要；完整版见 [publishing.md](../guides/publishing.md) §5.1 / §6）

1. **测试先绿**：tree-engine **112/112**；会话树 handoff 41/41、skills 3/3、render、style-guard 22/22、verify-bundle 0 fail、provider-conformance 29/29（rc.2 fixture）。
2. **版本纪律（D6）**：包内容有变化必须 bump `packages/dsh-session-tree/package.json` 的 version；无内容变化不制造假版本。**本轮会话树运行时行为未变**，但 `test/provider-conformance.cjs` 有改动（rc.2 fixture 解析），而 `release-plugin.mjs` 按**目录全量**同步（19 文件，含测试脚本）——是否发布以 `release-all.mjs --dry-run` 的「内容对账」为准：`files=N match=N` 才是 no-op；有变化就按 D6 bump 后发布。
3. **一条命令（W2.7）**：`node scripts/release-all.mjs --dry-run --mirror-dir <dir>` 先演练 → 需要真实发布时 `--push`。脚本串起：预检（分支/remote/镜像/版本/`release-plugin --check`/一致性脚本/测试）→ 单向同步 + SHA 对账 → 本仓 commit（可选 push）→ 镜像 commit + tag（可选 push）→ `ls-remote` 核对；失败即停并打印回滚命令。
4. **同步护栏**：仍只走 `scripts\release-plugin.mjs`，要求 `files=N match=N mismatch=0 missing=0 extra=0` + `RESULT: OK`；本轮公开镜像 **19/19 SHA**（v1.3.6）。禁止手工双写。
5. **镜像现状与发布判断**：公开镜像当前 `main` + tag = `v1.3.6`（`298298d`，19/19 SHA）。Wave 2 改的是本仓 tree-engine（未单独发仓）、脚本与文档；会话树**运行时文件未改**，但 `test/provider-conformance.cjs` 在同步范围内——因此 `release-all.mjs --dry-run` 可能报「版本未 bump」。处理方式二选一：① 需要把测试适配带到镜像 → bump 到 `1.3.7` 走发布；② 暂不发布 → 保留 v1.3.6，记录该差异（下次 bump 一并带出）。
6. **市场 / npm**：market 按 version 判断更新；**npm 冻结（D3）**，无动作。
7. **本仓自身**：提交前过 publishing.md §6 公开前检查清单（密钥扫描 / D7 排除项 / 测试 / 文档一致性）。

## 7. 已知边界（诚实清单）

1. **真机 E2E 三断言本体未执行（W2.5）**：`scripts/e2e/run-release-e2e.mjs` 已落地并完成离线故障注入（能 FAIL）、replay 正/负样本；真机 `verify-handoff` / `verify-kickoff-language` / `collect-skills` 需真实会话与配额，**发布前由 Lead / 人工触发**，CI 不跑真机。
2. **发布真推未执行（W2.7）**：`scripts/release-all.mjs` 只在隔离沙箱完成全链路本地演练（同步 19/19、本仓 commit、镜像 commit + tag、no-op 判定）；**本轮未做任何 commit/push、未推送远端**，正式发布由 Lead 以 `--push` 执行。
3. **预算口径漏接力前旧会话**：`max_sessions` 已计入 `runtime.segmentChain`（W2.1），但**接力前旧会话仅存 `runtime.history`，暂不计**（每个发生过接力的 leaf 约漏 1 个首派会话）。
4. **relay / dispatch 不预检预算**：`bambooRelay` / `dispatch:start` 本身不做预算预检，只有 `leaf:add` / `set-session` / `segment:append` / `tree:register-session` 会拒绝超限——**高频接力仍可静默越过上限**（后续轮候选）。
5. **两套预算口径有意不同**：`tree_status {action:"sessions"}` 的 reached 语义 = `count >= max`（预警），引擎拒绝 = `count > max`（超一格才拒）；读数和门禁不要混用。
6. **RC2 conformance 依赖本机 fixture**：29/29 依赖 `%TEMP%\dsh-asar-inspect\out-rc2-compat`（可被清理、随 DSH 版本布局漂移）；报告已固定来源与 SHA-256；缺 fixture 时 exit 2 + 可操作报错，属环境依赖而非代码失败。
7. **artifact 验证对象错位**：`**/*.md` 按字典序取首个匹配，可能命中 `node_modules` 里的 md；`minSize` 比较字符数而非字节（未修）。
8. **leaf.status 与 runtime 终态脱节**：runtime `succeeded` 后 `status` 可能停留 `pending_brief` / `active`（观察者易误读；收口看 `runtime.state`）。
9. **flash 审计积压**：33 条问题（[flaudit-report.md](../archive/flaudit-report.md)），严重级 3 条已抽查属实（`.lock` 文件锁未实现 / nudge 绕 `assertTransition` / `leafAdd` 字段透传无白名单）；采纳前逐条复核。
10. **未接项**：`observeSession` 事件面（宿主形状未冻结）、llm-judge 宿主 judge 端口、源 `tests/` 五个 `.test.cjs` 移植、sweep 用裸 `setInterval`（未托管 disposal）、完整性签名（D-v4）/ `E_CALLER_REQUIRED`（D-v2）。
11. **`tree_maintain gc` 未实现**：`tree-engine-data\` 下历史 smoke/e2e 测试树只能手工清理（先 backup 再删）。
12. **sweep 依赖宿主 timer**：宿主 timer 可用时用其 interval，不可用时 `systemClock()` 进程内 60s 兜底（`sweepMode` 恒为 `timer`）；不要假设「必须显式 harvest」。
13. **`provider-conformance` 是环境 + 布局双依赖**：rc.2 fixture 已可复现 29/29，但宿主布局再变仍需重新解包对账（[conformance-rc2-2026-11-12.md](../reports/conformance-rc2-2026-11-12.md)）。
14. 更早的踩坑记录（客户端模块契约 / Inspect Provider 写法 / 胶囊定位 / 工程纪律等）仍以 [handoff-2026-10-14.md](../archive/handoff-2026-10-14.md) §4–§5 为准。
