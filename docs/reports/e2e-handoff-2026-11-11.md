## 2. 环境与取证方法

- 主机：Windows，DSH Web GUI `http://127.0.0.1:5643`；仓库 `D:\Codes\dsh-tree-harness`。
- 解码运行时：bundled node `C:\Users\sir_c\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`（v24.21.0，`node:zlib` 提供 `zstdDecompressSync`）。
- 数据源（旁证口径，不依赖被测实现）：
  - 会话日志 `%USERPROFILE%\.dsh\sessions\--D-Codes-dsh-tree-harness--\<sessionId>\session.v4.jsonl.zstd`。
    **多 zstd frame 拼接**：Node 单次解压只出第一帧；本脚本扫描魔数 `28 B5 2F FD` 的每个位置逐帧 `zstdDecompressSync`（失败忽略），按 `type+seq` 去重后按 seq 排序。
  - 会话投影缓存 `%USERPROFILE%\.dsh\storages\session_projcache\sessions\<sessionId>.json`（`record.rows.permissions / agentPreset / modelSelection / workingDirectory`）。
  - 工作区注册表 `%USERPROFILE%\.dsh\storages\workspace.json`（`tables.workspaces.<id>.path / sessionIds`）——**侧栏分组归属的权威证据**。
- 断言口径：
  - 源“生效态”取 projcache 当前投影（缺失回退到日志最后一个 `permission/preset`、`sandbox/mode`、`approval/policy` 事件）；successor 取**首帧事件**。
  - 工具数与 requestHeader config 取 successor **首帧** vs 源**最近一帧** `request/header`。
  - `handoff_file_read`：只认真正返回文件内容的读取证据（`read` 工具调用且 `file_path` 指向 HANDOFF 文件；或 tool/result 含 `<path>…HANDOFF….md</path>` / `# Session handoff` 正文）；`why_check/why_file/glob/grep` 等元数据查询与“模型口头声称读过”只记为弱证据，不计 PASS。
  - sibling 接替是 continuable subagent 会话，按 DSH 现有设计**不登记**到 `workspace.sessionIds`；此路径断言“与源同归属状态（都未登记）”，不要求入册。root 路径则严格要求入册。
