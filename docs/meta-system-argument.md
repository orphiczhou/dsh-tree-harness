## 0. 观察底座与主链映射

**系统第一人称**：我是 dsh-tree-harness——一个树形任务分解执行基座。我的存在意义是被消费（Nanju 或任意编排器经我的工具面驱动任务树），我的稳定 = 在现实扰动（长任务、并发、崩溃、超时、成本、对抗性输入）下持续交付可信的执行与验证裁决。

**方法论四环节的映射**（现实作用 → 系统反应 → 稳定影响 → 反馈返回）：

| 方法论环节 | 本系统对应 |
|---|---|
| 现实作用 | 任务树建入（tree_plan/node）、节点派发（tree_dispatch）、竹节触发（上下文水位） |
| 系统反应 | 引擎调度子会话、串行队列落盘、sweep 收割、验证策略裁决 |
| 稳定影响 | 节点终态落定、护栏生效（预算/深度/链长）、接口缝对外不变 |
| 反馈返回 | 收割结果回写、断言失败、事故（macp2 型爆炸）、用户实机反馈、下游消费偏差 |

**主链定位**：本仓当前处于**第一轮主链的「策划→决策」之间**——反馈已充分（§1），分析待系统化（§2），策划与决策是本文档主体（§3/§4），实施=S0/S1（§5），反馈返回=验收断言+实机+下一轮递归触发（§5.3）。

## 2. 分析：1115 法建立坐标

### 2.1 一横：相关系统展开

| 系统 | 供给（作用） | 约束（反作用） | 断链风险 |
|---|---|---|---|
| DSH 宿主 | subagents/timer/sessionQuery/storage/tokenMeter/approval | 委派深度≤3、并发≤20、审批策略运行时可变 | 深度语义误读（逻辑深度≠嵌套深度）；approval=never 影响 human 模式 |
| 源引擎（Proma-Easy） | 规约真源：dispatch 表、护栏、竹节、help 全文 | 316KB 加固产物，行为保真难（R1 风险） | **tree-mcp-tools.ts 已断**（A 断点） |
| 现役插件生态 | session-tree 树视图（复用）、tree_send 先例（prompt 授权范式） | Loader 缓存约束迭代节奏 | 无（已实证） |
| 下游 Nanju | 未来消费方，倒逼接口缝稳定 | 不得泄漏进引擎概念 | 接口缝未经真实消费检验 |
| Loader/HMR | 新包名即装即生效 | 已装载包改动须重启 | 开发期迭代被缓存拖慢（R5） |
| 外部 LLM 供应商 | 13 组模型路由（执行者/评审者异构可选） | token 成本（llm-judge 放大 R4、竹节冷启动成本） | 供应商侧配额/费率变化 |
| 用户 | 最终验收 + 竹节类需求信号 | 无浏览器控制能力时验证止于三层证据 | 视觉验证依赖用户刷新页面 |

## 4. 决策：APX + 相位裕度 + 自适应

### 4.1 APX 候选方向裁决（A=候选方向集，P=向心关系〔对稳定对象 Z 的引力/斥力〕，X=裁决）

| # | 候选方向 | 向心关系（+引/−斥） | 裁决 |
|---|---|---|---|
| D1 | S0 首日先闭 A 断点再冻结规约 | Z5+Z1 强引；顺序成本≈0 | **选**（正源前置） |
| D2 | 竹节并入 S0 一并冻结（vs 后置 S1.5） | Z2/Z6 双向（新语义扰动 vs 早日闭链）；用户需求已到 | **选**（用户已裁） |
| D3 | 验证层分批：第一批 self-report/artifact/command，llm-judge/composite/human 第二批 | Z3 稳步逼近，成本可控（R4） | 选（继承原计划） |
| D4 | 平铺派发模式 | 深度墙（>3 层逻辑树）的逃生门；但丢嵌套视图与子树隔离，维护双模式稀释 Z1 | **缓**：S0 记为条件项——仅当真实任务出现 >3 层需求才启用（聚合节点降级优先） |
| D5 | 面板复用 session-tree（不新建包） | Z4 无涉、成本−；S2 专用面板后置 | 选（已定，维持） |
| D6 | 护栏参数进 Config（vs 硬编码源引擎缺省） | Z6 引（运行时可调不重编译）；风险=误配 | 选：类型/约束类装载期校验兜底（冻结版 §4.7 分级） |
| D7 | 竹节全自动（vs 保留哨兵半自动为主） | 自动化消除单点哨兵依赖；新增误触风险由链长上限+先到者语义兜住 | 选（自动为主，手动 action 兜底） |
| D8 | llm-judge 每节点启用（vs 仅高危 taskType） | Z3+ 但 R4 成本放大 | **弃缺省**：仅高危类型映射启用，self-report 兜底（继承 R4 对策） |

**向心收敛判据**：所有「选」的方向均指向同一核心——七功能闭环 + 六稳定对象不破；无离心方向入选。

### 4.2 相位裕度评估（剩余稳定空间）

相位裕度 = 系统距失稳的可测距离。逐稳定对象建立「偏差信号 → 裕度」监控面：

| 对象 | 偏差信号（可测） | 当前估计 | 消耗裕度的动作 | 恢复动作 |
|---|---|---|---|---|
| Z1 一致性 | 并发写冲突率、重建幂等失败数 | 0（设计态）；裕度=串行队列吞吐上限 | 多会话高频写同一树 | 队列背压 + tree_maintain 归档分流 |
| Z2 硬截止 | 超时判定误差 = 实际落定时刻 −（阈值+sweep 周期） | 设计承诺 ≤ sweep 周期（60s）；竹节后新会话重置基准即保护 | sweep 周期拉长、事件面失效叠加 | sweepMode 字段如实暴露；降级告警不静默 |
| Z3 独立性 | 评审者与执行者同族率（目标 0） | 设计态 0；白名单 3+ 族供轮换 | 族供应短缺（某族不可用） | 家族枚举回退序（避让轮换，冻结版 §10 先例） |
| Z4 接口缝 | 工具 schema 变更次数（冻结后目标 0） | 0；竹节并入会 +1 次版本化变更 | S0 后随意改签名 | 缝变更走版本化 + Nanju 消费方对账 |
| Z5 保真 | 差分测试非白名单字段差异数 | 0（金标准建立后）；**A 断点未闭前裕度未知** | 规约理解偏差进入重写 | 最小复现输入回溯 engine-spec 修订 |
| Z6 资源 | 并发占用/20、树会话数/50、竹节链长/5、llm-judge 调用/预算 | 全 0（空载）；**并发 20 是最紧的墙**（宽树 + 竹节接力瞬时双会话） | 宽树并发派发 + 接力瞬时重叠 | 引擎派发闸（并发水位<20 才派）；竹节先 interrupt 后 start（串行接力，设计已含） |

**最紧裕度判定**：Z6 并发墙。竹节接力若"先 start 新会话再 interrupt 旧会话"会瞬时占用 2 名额，宽树下可击穿 20 上限——**决策：竹节必须先 interrupt 后 start**（写入 S0 规约，修正 segment-handoff.md 流程第 4 步的表述顺序）。
