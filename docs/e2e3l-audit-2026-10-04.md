## 三、异常与偏差

1. **[现象·契约内] leaf.status 与 runtime 终态脱节**:4 个 worker 在 runtime succeeded 后 `status` 仍为 `pending_brief`,两个 commander 与 root 仍为 `active`,全程未见 `set-status` 调用(call-log 中无 `leaf:set-status` 行)。任务契约已说明引擎语义以 runtime 终态为准,故不算违约;但 status 字段成为陈旧数据,任何只读 leaf.status 的外部观察者会得到错误结论,建议引擎在 done/succeeded 时同步收敛 status 或文档显著标注。
2. **[偏差·中等] doc 任务的 artifact 验证对象错位**:C1b、C2b 的 verification verdict(mode=artifact, pass=true)指向 `node_modules\@local\dsh-tree-engine\tests\diff.DEVIATIONS.md`,而非本树实际产物 `demo\e2e3l\findings.md` / `report.md`。即 doc 策略的 artifact 匹配没有绑定 leaf 实际产出文件,验证"通过"的凭据与被验证产物无关——D 项的 pass=true 存在水份,产物真实性实际由 G 项(审计员直接读文件)背书,而非引擎验证背书。
3. **[噪声·轻微] call-log 中的失败试探**:行 6 `leaf:add ok=false E_SCHEMA_INVALID ("leaf_id is required")`;行 8 `E_LEAF_NOT_FOUND "e2e3l-C1b-worker" not found`(C2 commander 在 C1b 尚未创建时即试图 add C2a 引用它,15:10:20 < C1b 创建 15:10:21,后重试成功)。属执行者格式/时序试探,未影响终态,但说明跨分支依赖的 add 需容忍竞态重试。
4. **[噪声·轻微] done 之后的尾部写入**:15:15:00 出现一批 done 之后追加的 progress 事件与 set-verification(commander 的 default 验证),以及 C1-commander/C2-commander 的 verification 时间(15:15:00)晚于其 done(15:12:26 / 15:14:32)。终态不受影响,仅时序上验证是事后补做的。
5. **[观察] root 无 runtime、无 events、无 verification**:契约将 root 排除在"六业务节点"外,故记为观察而非偏差。

未发现执行者报告与落盘数据矛盾之处(本审计未采信任何执行者自述,仅以数据为准;所有核验项均直接来自 tree-state.json / call-log.jsonl / 产物文件)。
