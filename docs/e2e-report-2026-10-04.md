## 逐步结果

| 步骤 | 工具 | 结果 | 备注 |
|---|---|---|---|
| 0 会话 id 获取 | pwsh `$env:DSH_SESSION_ID` | ✅ | id 为裸 UUID（无 session- 前缀，与环境变量先例不同） |
| 1 建树 | tree_plan create | ✅ | `created tree e2eloop`（fs 持久化跨进程生效） |
| 2 节点登记 | tree_node add | ⚠️→✅ | **发现 A**：`session_id:null` 与 root 的 null 判冲突（E_SCHEMA_INVALID）；省略字段后成功 |
| 3 真实派发 | tree_dispatch start | ❌ | **发现 B（主断点）**：`E_PORTS_PROTOCOL: Cannot read properties of undefined (reading 'id')` |
| 4-6 收割/竹节 | 依赖步骤 3 | — | 孙会话未创建，跳过；**发现 C**：harvest/node get 的渲染过简，runtime 字段在工具结果里不可直读 |

## 发现与修复（v0.3.4）

| # | 发现 | 根因 | 修复 |
|---|---|---|---|
| A | null 会话 leaf add 被拒 | `findSessionConflict` 未跳过 null（PENDING 型会话与 root.session_id=null 互撞） | engine.js leafAdd：`session_id != null` 才做冲突/预算检查（源引擎 PENDING 语义对齐）；回归测试覆盖 |
| B | dispatch 崩溃 | asar 静态分析误判"request.parent 由服务侧解析"——**实况：startContinuable 内部对 `parent.id` 解引用且要求 `ctx.agents.get(parent.id) === parent`（活 Agent 强校验）** | 端到端修正：tree_dispatch 工具调用传 `exec.agent`（活派发者）→ ports.dispatch 的 `request.parent`；宿主 parents 捕获表（Map, 进程内）供竹节接力复用；runtime 落 `parentSessionId`。E2E 形状证据链：dispatch 需活 Agent / interrupt 需 `{kind:'parent', parentSessionId}` 持久地址（asar L852） |
| C | 可观测性弱 | harvest render 一句带过；node get 的 runtime 在结果 JSON 里其实有（dispatch 失败时确无） | harvest render 展开逐树事件（`tree:event(relay)` 格式）；runtime 观测依赖修复 B 后自然可用 |

## 结论与下一步

1. **闭环剩两环未实证**：真实收割（孙会话落定 → runtime 终态）与竹节接力（v0.3.4 修复后需重启加载再测）；
2. v0.3.4 的 parents 捕获表引入一个已知边界：**竹节接力要求首派发者会话仍存活**（活 Agent 引用），死亡时接力 fail-closed（节点保持 running，下轮 sweep 重试）——设计上可接受（长任务的派发者通常存活），记入边界清单；
3. 下次装载 smoke（重启后）：重跑本报告步骤 3-6，预期闭环走通；随后按开发计划推进 usagePct 宿主测量与验证层第二批。

**测试状态**：v0.3.4 = 44/44 绿（新增 E2E 回归 2 项：null 会话登记、parentAgent/parentSessionId 透传断言）。
