## 发现与修复（v0.3.4）

| # | 发现 | 根因 | 修复 |
|---|---|---|---|
| A | null 会话 leaf add 被拒 | `findSessionConflict` 未跳过 null（PENDING 型会话与 root.session_id=null 互撞） | engine.js leafAdd：`session_id != null` 才做冲突/预算检查（源引擎 PENDING 语义对齐）；回归测试覆盖 |
| B | dispatch 崩溃 | asar 静态分析误判"request.parent 由服务侧解析"——**实况：startContinuable 内部对 `parent.id` 解引用且要求 `ctx.agents.get(parent.id) === parent`（活 Agent 强校验）** | 端到端修正：tree_dispatch 工具调用传 `exec.agent`（活派发者）→ ports.dispatch 的 `request.parent`；宿主 parents 捕获表（Map, 进程内）供竹节接力复用；runtime 落 `parentSessionId`。E2E 形状证据链：dispatch 需活 Agent / interrupt 需 `{kind:'parent', parentSessionId}` 持久地址（asar L852） |
| C | 可观测性弱 | harvest render 一句带过；node get 的 runtime 在结果 JSON 里其实有（dispatch 失败时确无） | harvest render 展开逐树事件（`tree:event(relay)` 格式）；runtime 观测依赖修复 B 后自然可用 |

## 结论与下一步

1. **闭环剩两环未实证**：真实收割（孙会话落定 → runtime 终态）与竹节接力（v0.3.4 修复后需重启加载再测）；
2. v0.3.4 的 parents 捕获表引入一个已知边界：**竹节接力要求首派发者会话仍存活**（活 Agent 引用），死亡时接力 fail-closed（节点保持 running，下轮 sweep 重试）——设计上可接受（长任务的派发者通常存活），记入边界清单；
3. 下次装载 smoke（重启后）：重跑本报告步骤 3-6，预期闭环走通；随后按开发计划推进 usagePct 宿主测量与验证层第二批。

**测试状态**：v0.3.4 = 44/44 绿（新增 E2E 回归 2 项：null 会话登记、parentAgent/parentSessionId 透传断言）。

### 逐步结果

| 步骤 | 结果 | 备注 |
|---|---|---|
| 3 真实派发 | ✅ | v0.3.5 修复（mechanism/agentOptions/signal）后起飞无异常；孙会话真实创建并回话 |
| 4 执行者结算 | ❌→✅ | **发现 D（主）**：执行者无法自举结算（详见下）；v0.3.6 修复后全自动 |
| 5 终态回流 | ❌→✅ | **发现 E**：`succeeded` 全引擎无赋值点，runtime 永卡 running 到 timeout；v0.3.6 双路径回流 |

### 发现与修复（v0.3.6）

| # | 发现 | 根因 | 修复（回归 3 项） |
|---|---|---|---|
| D | 执行者调 set-session 被拒（E_BORROWED_IDENTITY）；done 事件所有权 caller===leaf.session_id 永不可满足 | dispatchStart 不绑定执行者会话；set-session 仅 creator 可调；派发提示词无结算指令（源引擎 54KB worker SKILL 的职责，移植时丢失） | ① dispatchStart 自动绑定 `leaf.session_id = 执行者会话`（重派绑最新）；② 派发提示词注入「结算指令」段（tree_report done 的 tree_id/leaf_id/格式） |
| E | runtime 终态闭集 `succeeded|failed` 无任何赋值点 | eventAppend 只 push 事件不触 runtime；sweep 只有 timeout/bamboo | ③ eventAppend：done 事件即时回流 `running→succeeded`（含 history 记录）；④ sweepTick：done+running 遗留形状兜底回流（治愈存量卡死节点） |

### 残余观察（未修，登记待裁决）

1. **leaf.status 与 runtime.state 双轨不同步**：runtime=succeeded 后 leaf.status 仍 `pending_brief`；按冻结版 done 三重闸，叶面 done 需 owner set-status + milestones audit_pass——是否由回流自动触发（跳过/自动过闸）需 S0 裁决，本轮未动；
2. sweep 对历史遗留树（e2eloop 等）的竹节接力端口报 `inactive context`（subagents/sessionQuery 取不到）——旧会话死亡时 fail-closed 符合设计，但日志噪音可考虑降噪；
3. tree_node get/set-session 渲染仍偏简（`status=undefined` 直出）；
4. PowerShell 控制台中文显示乱码为**显示层编码**（磁盘 UTF-8 JSON 实测 VALID）——非引擎缺陷，排查时勿误判。

**测试状态**：v0.3.6 = 47/47 绿（新增 E2E#5a/5b/5c：自动绑定+done 自举、事件路径回流、sweep 兜底回流）。
